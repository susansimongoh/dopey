# Dopey: architecture, cost and intelligence audit
**Date:** 21 Oct 2026 · **Scope:** spsmedia.netlify.app (project `sps`) · **Evidence window:** 143 monitored days, 30 days of Apify billing

Every figure below is tagged:
**[V]** verified from code, database or vendor billing · **[I]** inferred from verified data · **[E]** estimate with the calculation shown · **[?]** not measurable with current access

## 1. Executive diagnosis

### 1.1 The product has no user. This is the finding that governs every other one. **[V]**

In the 59 days since the PM approval gate went live (25 Aug to 21 Oct):

| Signal | Count |
|---|---|
| Social clips queued `pending` | **300** |
| Clips approved | 126 |
| ...of which auto-approved (own SPS/YRSG accounts) | **123** |
| ...of which approved by a human | **3** |
| Clips rejected by a human | 8 |
| Stories hand-edited | **0** |
| Days a report number was set (i.e. a report was exported) | **1** (my own test) |
| Days with unactioned pending clips | **55 of 59** |

The queue is not noise. The top of it is the exact content that fills the team's *Issues Monitoring* section every day: ADPAN (40 clips across four platforms), Alliance Against Death Penalty (9), Mediacorp (25), Zaobao (29), Mothership (16).

**Cause, not symptom:** the gate was specified as "keep the social clip only if the PM approves" and built exactly that way. What was never built is the thing that makes any human-in-the-loop gate survive contact with a working week: a notification, a landing view that opens on the queue, and a default that fails *open* rather than closed. A gate with no nudge and no deadline is a dead letter queue. The system now spends real money every weekday to fill a queue nobody opens, and the highest-value section of the report has been silently empty for two months.

**This is reversible in about an hour** (§6.1) and it is worth more than every cost optimisation in this document combined.

### 1.2 We pay for ~1,120 posts a day to discover ~75. **[V]/[I]**

Verified per-sweep economics from Apify billing (30-day window, Dopey's 01:00-02:00 UTC sweep slot):

| Actor | $/sweep-day | Share |
|---|---|---|
| `apify/facebook-posts-scraper` | $1.111 | **48%** |
| `apify/instagram-scraper` | $0.573 | 25% |
| `clockworks/tiktok-scraper` | $0.593 | 25% |
| `apidojo/tweet-scraper` | $0.054 | 2% |
| **Total** | **$2.33** | |

$45.96 over ~20 sweep-days. At 21.7 weekday sweeps a month that is **~$50/month**, and Apify is **~97% of Dopey's marginal cost** (§5).

The funnel, measured across 56 sweep-days since 1 Aug **[V]**:

```
~1,120 posts requested from actors   (104 curated slots x 5) + (50 news slots x 12)   <- what we PAY for
    522 posts inside the 7-day window                                                  <- what we look at
      7.7 social clips kept                                                            <- 1.5% keep rate
      7.4 stories                                                                      <- the deliverable
```

In steady state the number of genuinely new posts entering a 7-day window each day is (posts in window)/7 = **~75/day [I]**. We pay for roughly 1,120 to find 75. **Cost per kept social clip: $0.30 [I].**

**Cause:** there is no source cursor anywhere in the system. Deduplication happens at the destination, in `mergeClips`, after the money is already spent. The actors are asked for "the latest N posts per account" every single day, and N was sized for a 7-day window rather than for the gap since the last sweep. The 7-day lookback is doing a real job (it is the weekend-recovery mechanism, Fri to Mon), but it is being paid for five times a week when it is only needed once.

### 1.3 40% of the fetch set has never produced anything. **[V]**

61 of 154 account-platform slots have not yielded a single kept clip in 143 days (40 curated, 21 news). They are swept at full depth every weekday regardless.

This is not an argument for deleting them. A dormant account's first relevant post is precisely the "important development" the product exists to catch. It is an argument for **cadence tiering**: a slot with no yield in 143 days does not need the same sweep frequency as ADPAN.

### 1.4 Enrichment has no negative cache, so it repeats on the same rejected posts forever. **[V]**

`runSocialFetch` OCRs up to 60 images per sweep, and `needsOcr` deliberately targets *posts that currently fail the gate* (correct design: OCR can only change a decision for a post that is failing). But posts that fail the gate never become clips, so nothing is persisted about them. The same failing posts return in tomorrow's 7-day window and get OCR'd again, for up to 5 weekday sweeps each.

Dollar impact is small (Gemini is ~$1.50/month total **[E]**), but it burns the Gemini rate-limit budget that OCR was throttled to respect in the first place, and it adds minutes to every sweep.

### 1.5 We cannot measure the incremental value of 3 of the 4 daily news fetches. **[V]**

`cron-news` runs news fetches at 11:00, 15:00 and 19:00 SGT on top of the 09:45 sweep. That change was made for a verified reason (CNA's RSS feed holds ~20 items and rotates within hours), and it is close to free. But clips carry **no `first_seen` timestamp**, so there is no way to answer "how many clips did the 19:00 run actually add?" The same blind spot prevents measuring re-fetch rates, detection latency, and the yield of any future cadence change.

**Instrumentation is the cheapest high-value change in this document.**

## 2. Architecture and cost map

### 2.1 End-to-end flow (verified by reading `netlify/lib/sps.mjs`, 1,412 lines)

```
                    cron-daily  45 1 * * 1-5   (09:45 SGT, weekdays)
                    cron-news   0 3,7,11 * * * (11/15/19 SGT, daily)
                            |
  ┌─────────────────────────┴──────────────────────────────┐
  │  NEWS PATH (free)                 SOCIAL PATH (metered) │
  │  outletFeeds()                    runSocialFetch()      │
  │   14 RSS feeds                     4 actors x 2 groups  │
  │   + confirmByBody()                concurrent Promise.all│
  │     <=18 article fetches/run       ~1,120 results asked  │
  └─────────────────────────┬──────────────────────────────┘
                            |
                  OCR  imageText()  <= 60 Gemini vision calls/sweep
                            |
                  mergeClips()  <- gate + dedup  (money already spent)
                            |
                  transcribeKeptReels()  <= 12 Gemini audio calls (POST-gate, correct)
                            |
                  reportDay() bucketing -> monitor_days.payload (whole-day JSONB RMW)
                            |
                  rebuildStories()  -> 1 batched Gemini call for NEW clusters only
                            |
                  [ APPROVAL GATE ]  <- 300 clips stuck here
                            |
                  DOCX / PDF export
```

### 2.2 Where money goes

| Layer | Provider | Model | Monthly | Confidence |
|---|---|---|---|---|
| Social sweep | Apify | per result returned | **$50** | **[V]** billing |
| Comment scraping | Apify | per comment | ~$0 (only 3 human approvals ever) | **[V]** |
| Gemini OCR / summaries / transcripts / sentiment | Google | tokens | **~$1.50** | **[E]** |
| Supabase | Supabase | within plan | $0 marginal | **[V]** 1.7MB total |
| Netlify functions + hosting | Netlify | within Pro | $0 marginal | **[V]** |

**[E] Gemini calculation:** ~60 OCR vision calls/day (~1k tokens each) + 1 batched summary call + <=12 reel transcripts (60s audio ~ 1,920 tokens) ~ 85k input tokens/day. At Flash list rates (~$0.30/M in, $2.50/M out) that is ~$0.05/day. Not verifiable without Google AI Studio billing access **[?]**.

**Apify charges for what the actor returns, not what we keep.** Blended observed rate: **$0.0028 per result** **[I]**, consistent across all four actors at 70-80% of list price, which also tells us actors return ~75% of the requested limit (many accounts simply have fewer recent posts).

### 2.4 What is working, and should not be touched

Honesty requires this section.

- **Reliability is excellent.** 1 error-day in 56 **[V]**. No outages since the July Apify cap incident.
- **Dedup is fixed.** 2 duplicate clips in 57 days, against 249 cleaned in August **[V]**.
- **Summarisation is sound.** 0 caption-fallback stories out of 316 since 1 Sep **[V]**: every story is LLM-backed, and `rebuildStories` correctly reuses prior summaries by clip overlap instead of re-paying for them.
- **Reel transcription is already correctly staged** (post-gate, capped), which is exactly the pattern §4 recommends generalising.
- **OCR targeting is already conditional** (only gate-failing posts). The design is right; it just lacks memory.

## 3. Intelligence quality

### 3.1 Coverage against the team's own reports **[V], but stale**

| Window | Dopey recall vs team | Measured |
|---|---|---|
| 1-16 Jul (reports 123-134) | ~44% | yes |
| 1-11 Aug (reports 146-151) | ~48% | yes |

Segment breakdown at the last full measurement (Aug): own-account and activist social ~76%, English news ~36%, vernacular 0% before the CJK fix. The fixes shipped since (SINGAPORE-dateline rescue, CJK/Tamil locale terms, body/description rescue, courts-crime class D, vocabulary batch, media-ring accounts) were each verified against the specific story that motivated them, but **their aggregate effect on recall has never been measured**, because measuring it requires team reports from September and October.

### 3.2 Known systematic blind spots **[V]**

- **Podcasts and radio** (CNA938 meListen, Capital 958, Oli 968 audio segments): no transcript source.
- **Print-only** (Shin Min, Tamil Murasu page scans via Meltwater): not reachable.
- **High-volume outlet socials are structurally incomplete.** CNA posts far more than 12 times a day on Facebook. At any limit we can afford, the news-outlet social sweep cannot be a discovery mechanism. It is a *citation* mechanism, and should be repositioned as one (§4.3). Discovery for those outlets already comes free from RSS.
- **One-off creators** (`aquajetgo`, `DamnLouisa`, `sg_footsal_network`): unreachable without keyword discovery, which was disabled for precision in July and should stay disabled.

### 3.3 Analysis quality

- **Traceability: good.** Every story links to its clips, each clip to its source URL, and the DOCX annex reproduces them.
- **Hallucination risk: low but unmeasured [?].** Summaries are generated from caption plus OCR plus transcript text only. There is no fact-check pass and no measured error rate. A 20-story spot-audit against sources would close this; it has never been run.
- **Sentiment lines: now mostly automatic but barely exercised.** 123 clips carry a Gemini sentiment line, nearly all from auto-approved own-account posts.
- **Traction tiers: deterministic**, from MM-Guide thresholds. Correctly not an LLM job.

### 3.4 Editorial productivity

Not measurable in the intended sense, because the editorial workflow is not being used (§1.1). What the data does show: to produce one report today a human must approve or reject every pending social clip (median ~5/day, up to 10), then write or accept stories, then export. **That first step is where the workflow is dying.**

## 4. Target architecture

Minimum change for maximum effect. No rebuild. The relational migration that a "proper" design would call for is **not** recommended: 144 rows and 1.7MB do not justify it.

### 4.1 Add a source registry (the one genuinely new component)

```sql
create table monitor_sources (
  project text, platform text, handle text,
  tier text default 'daily',        -- daily | twice_weekly
  last_swept_at timestamptz,
  last_yield_at timestamptz,        -- last time this slot produced a kept clip
  yield_count int default 0,
  primary key (project, platform, handle)
);
```

Drives three things: which slots are due today, what depth to request, and an evidence trail for every future cadence decision. Backfillable from the existing archive in one query.

### 4.2 Gap-aware depth instead of fixed depth

The current `limit` is sized for a 7-day window and charged 5 times a week. Size it for **the gap since the last sweep** instead.

| Day | Gap | Curated depth | News depth |
|---|---|---|---|
| Monday | 3 days | 6 | 16 |
| Tue-Fri | 1 day | 2 | 5 |

Weekly requested volume: 1,424 + (4 x 458) = **3,256 vs 5,600 today (58%)**. Monday coverage *improves* over today's 12. Set `social_lookback_days` to 4 (it only ever needed to cover Fri to Mon).

### 4.3 Reposition news-outlet socials as citation, not discovery

Discovery for ST/CNA/Mothership/Zaobao is already handled free by RSS plus `confirmByBody`. Their social sweep exists to supply the "(Facebook)" citation and engagement figures. Depth 5 on weekdays serves that; depth 12 does not buy completeness it can never achieve.

### 4.4 Two caches, both tiny

- **Seen-post cache** (`seen_posts(id, last_seen)`): skip enrichment and gate evaluation for any post ID already judged. Does not reduce Apify spend (the actor already returned it), but removes repeat OCR, repeat body fetches and most sweep latency.
- **Negative-enrichment cache**: a post OCR'd once and still failing is never OCR'd again. Kills §1.4 outright.

### 4.5 Fail-open editorial gate

Keep the PM's veto. Change the default. See §6.1.

### 4.6 Instrumentation (do this first)

Add `first_seen` to every clip and a per-run `{requested, returned, new, kept}` record on the day payload. Without it, no cadence or frequency claim in this document can be independently verified after the fact.

## 5. Cost model

Baseline **[V]**: $50.6/month Apify (21.7 weekday sweeps x $2.33), $1.50 Gemini **[E]**, $0 marginal elsewhere.

| Scenario | Weekly requested | vs today | Monthly Apify | Saving |
|---|---|---|---|---|
| **Today** | 5,600 | 100% | **$50.60** | - |
| **A. Gap-aware depth** (§4.2-4.3) | 3,256 | 58% | **$29.30** | **$21.30 (42%)** |
| **B. A + cadence tiering** of 61 never-productive slots to Mon+Thu | 2,701 | 48% | **$24.40** | **$26.20 (52%)** |

Scaling assumption, stated plainly: Apify bills per result returned, so cost scales linearly with requested volume at the observed blended $0.0028/result. Verified consistent across all four actors **[I]**.

**Volume scenarios** (same config, different news intensity):

| | Posts in window/day | Monthly Apify today | Under B |
|---|---|---|---|
| Quiet | ~350 | ~$38 | ~$18 |
| Typical (measured) | 522 | $50.60 | $24.40 |
| Heavy (election, major case) | ~750 | ~$68 | ~$33 |

**Trade-offs, stated honestly:**
- Scenario A has **no coverage cost** and improves Monday depth. The only risk is a curated account posting more than twice between weekday sweeps, which the archive shows is rare.
- Scenario B accepts **up to 3 days of detection delay on accounts that have produced nothing in 143 days**. Report-day bucketing means a late-found post still lands on the correct report page, so the real cost is "reported a day or two late", not "lost". I would exclude from tiering any account the team's own reports have ever cited, whatever its Dopey yield.
- Neither scenario touches the news RSS path, which is free and carries most discovery.

## 7. Validation framework

Anyone should be able to run this without me.

**Gold-standard dataset.** 15 monitoring days of team reports: 5 high-volume weekdays, 3 quiet days, 3 Monday multi-day reports, 2 days with a major multi-outlet story, 2 days with vernacular-only coverage. Each team story labelled with its sources. **This is the single missing input** — the most recent team report on file is #160 (24 Aug).

**Metrics and thresholds:**

| Metric | Definition | Threshold |
|---|---|---|
| Critical-story recall | team "News Highlights" + "Issues Monitoring" stories found by Dopey | **non-regression: must not fall below the pre-change measurement.** Hard gate on any cost change |
| Overall recall | all team stories found | >= 65% target |
| Precision | kept clips a human judges reportable | >= 70% |
| Duplicate rate | same post clipped twice | < 1% (currently 0.3% **[V]**) |
| Cost per kept clip | Apify $ / kept clips | from $0.30 to <= $0.15 |
| Cost per report | Apify $ / exported report | report first |
| Time to report | queue open to DOCX export | < 20 min |
| Sweep reliability | error-free sweep days | >= 95% (currently 98% **[V]**) |

**Procedure.** Freeze config. Run current and proposed settings on alternating days for two weeks (A/B by date, same sources, same gate). Compare recall against the gold set and cost against Apify billing for those exact run IDs. Historical replay cannot reproduce retrieval cost, because Apify bills at fetch time and the archive holds only survivors, so **a controlled live A/B is required**; it costs roughly one normal month of spend.

**Security and isolation tests** (none currently automated **[?]**): per-project key resolution falls back correctly when `*_SPS` is absent; a `client`-role user cannot read another project's days; no credential appears in any deploy artifact (the Netlify secret scanner caught one in August and silently failed deploys for five weeks); rejected clips never resurrect; `dismissed` survives re-sweep.
